# AGENTS.md

This file provides guidance to AI agents when working with code in this repository.

## What this is

Jump'n'Bump — a 1998 DOS game by Brainchild Design, ported to Linux/SDL. Original source is old, monolithic C (the author's own words: "the code is poorly designed, making changes to it is hard, if not impossible"). Treat `main.c` as legacy code to work around carefully rather than a clean codebase to refactor freely.

## Target layout

This repo is mid-port to a `core/` (Zig simulation) + `include/` (frozen C ABI) + `extension/` (GDExtension shim) + `game/` (Godot project) + `tools/` (asset pipeline) layout — see `backlog/tasks/` for the full plan. The legacy `main.c`, `sdl/`, and `modify/` tree is retained forever, not deleted once the new tree lands: it's the differential-test oracle the new Zig simulation core is checked against frame-by-frame (`TASK-008`), so any behavioral drift in the port shows up as a failing diff rather than a silent regression.

## Docs

- `docs/porting-playbook.md` — the incremental C-to-Zig porting procedure: one subsystem at a time, ABI-compatible exports, the no-`@import`-between-ported-modules rule, and the four-tier verification ladder (unit/differential/ABI-conformance/Godot-replay), including Jump'n'Bump's no-float simulation constraints.
- `docs/build-layout.md` — the full target directory layout and how `core/`, `include/`, `extension/`, `game/`, and `tools/` fit together with the legacy build.
- `docs/development.md` — local dev workflow notes: `act`'s sharp edges (architecture mismatch, `--reuse` volume persistence, `.dockerignore` not applying) and known CI task-graph gaps.

## Build

Requires SDL 1.2, SDL_mixer, SDL_net, zlib, bzip2 dev packages (Debian/Ubuntu: `apt-get install libsdl-dev libsdl-mixer-dev`).

```sh
make            # builds sdl.a (via sdl/), gobpack/jnbpack/jnbunpack (via modify/), then jumpnbump, then game data
make clean      # cleans sdl/, modify/, data/, and top-level objects/binaries
make install    # PREFIX=/usr/local by default; installs to $(PREFIX)/games and $(PREFIX)/share/jumpnbump
```

Zig tests run via `core/build.zig`'s four steps (`test`/`difftest`/`abi`/`abitest` — see `docs/build-layout.md`). Linting runs through `prek`/`.pre-commit-config.yaml` (ruff, markdownlint, standard hygiene hooks). `task check` is the single documented gate.

### Build graph

- `globals.h` is generated from `globals.pre` (sed substitutes `%%PREFIX%%`) — always regenerated by `make`, never edit `globals.h` directly.
- `sdl/` builds `sdl.a`, the SDL backend (graphics, sound, input, interrupts) linked into the main binary.
- `modify/` builds three standalone tools — `gobpack`, `jnbpack`, `jnbunpack` — used to pack game assets.
- `data/` uses `gobpack`/`jnbpack` to compile raw assets (`.pcx`, `.mod`, `.smp`, `.txt`) into `jumpbump.dat`, the runtime data archive loaded by the game at startup.
- The top-level `Makefile` links `fireworks.o main.o menu.o filter.o` against `sdl.a` to produce the `jumpnbump` binary.

## Architecture

- `main.c` is the core of the game: initialization, the main game loop, physics/collision, level loading, menu-loop glue, and networked multiplayer (client/server packet protocol over UDP via SDL_net) all live here in one file. Function names are the map — grep `main.c` rather than expecting separate modules per concern (e.g. `game_loop`, `menu_loop`, `init_program`, `collision_check`, `cpu_move`, `steer_players`, `update_objects`, `init_server`/`connect_to_server` for netplay).
- `menu.c` — in-game menu system UI.
- `filter.c`/`filter.h` — pixel scaling/filter routines for display scaling.
- `fireworks.c` — the `-fireworks` screensaver mode.
- `sdl/` — platform backend: `gfx.c` (video/blitting), `sound.c` (SDL_mixer audio), `input.c` (keyboard/joystick), `interrpt.c` (timer callback).
- `dos/` — legacy DOS backend (DJGPP/nasm-era), parallel to `sdl/`; not part of the default Linux build.
- `modify/` — asset packer/unpacker CLI tools (`gobpack`, `jnbpack`, `jnbunpack`) used both to build `data/jumpbump.dat` and by end users to build custom levels (see `levelmaking/`).
- `data/` — raw game assets and the Makefile that packs them into `jumpbump.dat`.
- `PB/` — Xcode/macOS port (`SDLMain.m`/`.h`, Project Builder project).
- `VisualC6/` — Windows/MSVC6 project files for the game and the pack/unpack tools.
- `dj.h` — DJGPP compatibility shim for the DOS build.

## Runtime notes

- Custom levels are loaded via `jumpnbump -dat levelname.dat`; level packing/format is documented in `levelmaking/`.
- Multiplayer is peer-to-peer-ish client/server over UDP, driven by `-net`/`-port` CLI flags (see `README` for exact invocation); the packet protocol (`NetPacket`, `sendPacket`/`grabPacket`/`processMovePacket` etc.) lives entirely in `main.c`.
- Build-time feature flags come from Makefile `CFLAGS`: `USE_SDL`, `USE_NET`, `ZLIB_SUPPORT`, `BZLIB_SUPPORT` gate SDL netcode and gzip/bzip2 compressed level support respectively.
